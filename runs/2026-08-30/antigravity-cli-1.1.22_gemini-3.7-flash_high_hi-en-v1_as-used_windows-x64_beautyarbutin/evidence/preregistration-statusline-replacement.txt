## Why this replacement exists

After one valid quota-only TUI attempt, the contributor checked Antigravity
CLI 1.1.22's official documentation and found the supported status-line JSON
interface. It exposes context_window.total_input_tokens,
total_output_tokens, current_usage.input_tokens, output_tokens,
cache_creation_input_tokens, and cache_read_input_tokens to a local command.
The quota-only attempt is retained outside Git as a superseded attempt; it is
not deleted and is not counted among the three new valid attempts.

The original preregistration also hashed the shared desktop-product settings
file. This replacement corrects the configuration source to Antigravity CLI's
official settings path.

## Fixed interactive procedure

For each attempt, start one new `agy` process from the attempt's independent
empty non-Git directory. Confirm Gemini 3.7 Flash and high, and confirm the
status line is active before sending the prompt. Type the exact two characters
`hi` once and wait for the final response. Capture the response together with
the safe status-line token summary, open `/usage` and capture the complete quota
panel, then exit without resume or continuation.

Only the run directory changes across R1, R2, and R3. Any settings hash,
script hash, model, effort, plugin, MCP, skill, hook, or permission change
invalidates the attempt and requires another replacement preregistration.

## Frozen measurement scope

remain not_exposed. No token, credit, cost, or subscription conversion is
inferred from quota percentage-point changes.
