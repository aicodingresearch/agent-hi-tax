## Fixed paired procedure

Pair order is fixed as CLI R1, Desktop R1, CLI R2, Desktop R2, CLI R3,
Desktop R3. For each Desktop attempt, open its pre-created project bound only
to the corresponding empty directory and start a new conversation. Confirm
Gemini 3.7 Flash High, capture a pre-prompt quota view, type exactly `hi` once,
wait for the final response, capture the response, capture the post-response
quota view, record the conversation identifier privately if exposed, then end
without adding another turn or reusing the conversation.

Only the attempt directory and the intended surface change. Any model, effort,
project security/review setting, built-in inventory, plugin, MCP, skill, hook,
account, or prompt change invalidates the affected attempt and requires a
replacement preregistration before continuing.

## Frozen measurement scope

The official Desktop 2.0 UI does not expose per-conversation token counts or
response duration. Token and latency fields are therefore not_exposed. The
repository forbids client reverse engineering; opaque SQLite/Protobuf fields
will not be decoded or reported. Only official UI evidence is used.

The quota meter is account-scoped, rounded, and shared by both deliberately
alternated surfaces. Before/after views are retained as native snapshots, but
quota attribution is contaminated and no percentage-point change is converted
into tokens, credits, or money. Consequently this pair will characterize the
visible harness and evidence differences but will not claim an exact
Desktop-vs-CLI token delta.
